# Architecture

```
┌──────────────────────── l-gpui (bin, feature "ui") ────────────────────────┐
│ src/ui/mod.rs    LarkApp state, actions, keyboard input, timers           │
│ src/ui/views.rs  rendering of every screen (GPUI div/flex primitives)     │
│ src/ui/widgets.rs, theme.rs  buttons, avatars, pills; light theme #3370FF │
└───────────────┬────────────────────────────────────────────────────────────┘
                │ spawn_cli(job) → background executor → update UI
┌───────────────▼──────────── lgpui_core (lib, no GPUI) ─────────────────────┐
│ client.rs   Lark: typed facade (chats(), send_text(), agenda(), …)        │
│ domains/*   per-domain argument builders + tolerant JSON parsers          │
│ auth.rs     SignInState from `auth status --json` / error envelopes       │
│ runner.rs   spawn lark-cli, normalise envelope + errors, --as handling    │
│ json.rs, time.rs  tolerant lookups, timestamp parsing/formatting          │
└───────────────┬────────────────────────────────────────────────────────────┘
                │ std::process::Command (stdin closed, stdout/stderr piped)
          ┌─────▼─────┐
          │ lark-cli  │  official CLI: config, OAuth, tokens, HTTP
          └───────────┘
```

## Principles

* **lark-cli is the only backend.** l-gpui never stores credentials, never
  makes HTTP calls to Lark and never prints tokens. Errors shown in the UI
  pass through `runner::sanitize`, which truncates them and redacts long
  token-like words.
* **Clean room.** Behaviour is derived from lark-cli's public `--help` output
  and documented JSON shapes only.
* **UI thread never blocks.** `LarkApp::spawn_cli` runs each call on GPUI's
  background executor and applies the result on the UI thread.

## Runner and error normalisation

`Runner::run(args)`:

1. appends `--as $LARK_CLI_AS` (except for `auth`/`config`), runs `$LARK_CLI`
   (default `lark-cli`);
2. `normalize(exit_code, stdout, stderr)`:
   * finds the first JSON value in stdout, else stderr (warning lines are skipped);
   * `{"ok": false, "error": {...}}` → `CliError` by `error.type`/`subtype`:
     `config*` → `NotConfigured`, `auth/token/login/expired*` → `NotSignedIn`,
     anything else → `Api { message, hint }`;
   * exit code 3 without JSON → `NotConfigured`; other non-zero → `Exit`;
   * `{"ok": true, "data": X}` → `X`; bare payloads pass through unchanged.
3. spawn failure with `NotFound` → `NotInstalled`.

`CliError::needs_sign_in()` errors flip the UI back to the sign-in screen.

## Sign-in detection

`auth status --json` → `identity` = `user` | `bot` means signed in; `none`
or missing means signed out. The sign-in screen re-runs this every 4 s and
on "Check again"; when it turns signed-in the current view loads.

## Domain parsers

Each `domains/<name>.rs` has pure `*_args()` builders (unit-tested) and
`parse_*()` functions that look for result arrays under several keys and
wrappers (`json::find_array`) and read fields through fallback paths
(`json::first_str`). Unknown or missing fields degrade to empty strings
instead of errors, so minor lark-cli output changes don't break the app.

| Domain | Command | Array key(s) |
|---|---|---|
| im | `+chat-list --types p2p,group --sort active_time` | `chats` |
| im | `+chat-messages-list --order desc --no-reactions` | `messages` |
| im | `+messages-send --msg-type text --content {"text":…} --idempotency-key` | – |
| im | `+messages-search --query` | `messages` |
| calendar | `+agenda --start --end` | top-level array / `events` |
| task | `+get-my-tasks --complete=false`, `+complete`, `+create` | `items` |
| docs | `docs +search` (fallback `drive +search`), `wiki +space-list` | `results`, `spaces` |
| mail | `+triage --max [--query]`, `+message --html=false`, `+send --plain-text --confirm-send` | `messages` |
| contact | `+search-user --query` | `users` |
| approval | `tasks query --topic 1|2 --locale en-US` | `tasks` |
| minutes | `+search [--query]` | `items` |

Message text is sent with `--content` JSON rather than `--text` so input that
starts with `@` is never treated by lark-cli as a file reference. Mail is
sent with `--confirm-send` because the user explicitly pressed Send (without
it lark-cli only saves a draft).

## Tests

* Unit tests in every core module, against sample JSON.
* `tests/fake_cli.rs` runs the real `Runner` against
  `tests/fixtures/fake-lark-cli.sh`, a shell script emulating lark-cli
  (happy path, unconfigured exit 3, signed out, API error, `--as` forwarding).

## Packaging

* `packaging/l-gpui.desktop`, `assets/l-gpui.svg` and `assets/l-gpui-256.png`
  (original artwork; the PNG is generated by `packaging/make-icon.py`).
* `cargo deb` metadata in `Cargo.toml`.
* `.github/workflows/release.yml` builds the `.deb`, a Linux x86_64 tarball and
  `SHA256SUMS.txt` on `v*` tags.
